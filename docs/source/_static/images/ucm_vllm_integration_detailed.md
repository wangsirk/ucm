## 2. 请求处理完整流程

```mermaid
sequenceDiagram
    participant U as 用户
    participant S as vLLM Scheduler
    participant UcmConn as UcmConnector
    participant Store as UcmKVStore
    participant Storage as 外部存储
    participant Worker as vLLM Worker
    participant Attention as Attention Layer
    
    Note: 台下方的数字表示请求开始时， Scheduler 会调用 `request_begin()` 生成请求的块哈希
    ucmConn->request_begin()
    end
    ucmConn->store.lookup(block_ids)
    Store --> 返回命中信息
    ucmConn->update_state_after_alloc()
    Scheduler->update_state_after_alloc()
    Scheduler->build_connector_meta()
    end
    ucmConn->build_connector_meta()
    end
    Scheduler->发送 Scheduler输出给 Worker
 Worker.bind_connector metadata
    Worker-> start_load_kv()
    Worker->execute_model
    Model->执行
    注意: vLLM Worker 的注意力层是逐层执行
    UcmSparse.attention_begin()
    ucmSparse.attn_begin()
    ucmSparse.attention_finished
    ucmSparse.request_finished_in_worker
    end
    Model->执行完成
    模型执行器调用 `save_kv_caches()`
    ucmConn->save_kv_caches()
    end
    UcmConn->request_finished_in_scheduler
    end
```

## 3. 关键文件说明
| 文件 | 说明 |
| --- | 请根据下面的表格快速理解 UCM 和 vLLM 的集成关系：

| 层次 | 机制 | 说明 |
| --- | --- | | 
| **继承 vLLM 基类** | 通过 `--kv-transfer-config` 参数指定 UCM 连接器，UCM 的通过配置文件中的 `kv_connector` 字段指定具体的连接器类名（如配置中 `kv_connector` 为 `UCMConnector`，则 vLLM 会自动加载对应的 UCM 连接器。 |
 | | **配置驱动** | 通过配置选择不同的存储后端和稀疏算法
    | **Hook 机制**    通过 Monkey Patching 在运行时动态修改 vLLM 的行为
        - **vLLM 儿.9.2/0.9.2 版本**： UCM 的通过 Monkey Patching 方式与 vLLM 鷻加自定义逻辑
        - **vLLM 0.9.2+**： UCM 的通过 Monkey Patch 添加稀疏注意力等功能
        - **vLLM 0.11.0**： 添加了 `load-failure` patch，
        - **vLLM 0.9.2**： 添加了 `kv_role` 配置（区分 Prefill/Decode 角色)
        - **vLLM 0.11.0**： 添加了 `kv_role` 配置(区分 decode 角色)
    - | **Hook 机制** | | - 在 vLLM 的 Scheduler、模型执行器、注意力层等关键位置注入自定义逻辑
    - | **vLLM 0.9.2** 的 `kv_connector` 配置中添加了 `kv_connector_metadata` 字段，用于传递元数据
    - | **vLLM 0.9.2** 的 `SchedulerOutput` 类中添加了 `req_sparsed_slots` 字段
    - | **vLLM 0.9.2** 的 `Model_runner.execute_model` 方法中添加了 `kv_connector_metadata` 参数
    - | **vLLM 0.9.2** 的 `Attention` 层中， UCM 通过 `attention_begin()` 和 `attention_finished()` 注入稀疏注意力逻辑
    - | **vLLM 0.9.2** 的 `Decoder_layer` 中， UCM 通过 `layer_begin()` 和 `layer_finished()` 注入逐层处理逻辑
    - | **vLLM 0.9.2** 的 `model.forward` 方法中， UCM 通过 `build_sparse_meta()` 构建元数据
    - | **vLLM 0.9.2** 的 `model_runner.execute_model` 方法中， UCM 的 `register_kv_caches()` 注册 KV 缓存
    - **vLLM 0.9.2** 的 `model_runner.execute_model` 方法中， UCM 的 `start_load_kv()` 加载 KV 缓存
    - **vLLM 0.9.2** 的 `model_runner.execute_model` 方法中， UCM 的 `save_kv_caches()` 保存 KV 缓存
    - **vLLM 0.9.2** 的 `model_runner.execute_model` 方法中， UCM 的 `wait_for_load()` 等待加载完成
    - **vLLM 0.9.2** 的 `model_runner.execute_model` 方法中， UCM 的 `request_finished()` 清理资源
```

## 4. 两种连接器对比

| 特性 | UCMDirectConnector | UCMLayerWiseConnector |
|------|-------------------------|-------------------------|
| 模式 | 同步加载/保存 | 逐层加载/保存，计算与I/O重叠 |
| 适用场景 | 简单场景 | 复杂长序列场景 |
| 性能 | 獭取延迟优先 | 流水线重叠优先 |
| 实现复杂度 | 中等 | 较高 |

## 5. 配置驱动
通过 `--kv-transfer-config` 参数将 UCM 配置传递给 vLLM：

```json
{
    "kv_connector": "UCMConnector",
    "kv_connector_module_path": "ucm.integration.vllm.ucm_connector",
    "kv_role": "kv_producer",  // 或 "kv_consumer"
    "kv_connector_extra_config": {
        "ucm_connector_name": "UcmNfsStore",
        "ucm_connector_config": {
            "storage_backends": "/mnt/test1",
            "transferStreamNumber": 32
        }
    }
}
```
